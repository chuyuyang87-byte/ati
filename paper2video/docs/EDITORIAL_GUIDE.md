# Paper2Video 科普编导规则

这是可测试的创作假设，不是对小红书、抖音播放量的已核实研究。
当前没有可用的站内搜索或视频观看工具；不编造热门账号、案例或流量数据。
收到用户参考链接后，在本文件记录可访问的内容、数据日期与无法验证的部分。

## 编导流程

1. 从论文原文建立证据；术语、结果和局限必须有原文页码与短引文。
2. 编导先产出一句核心问题、生活类比、开场悬念和最终回答。
3. 前3秒抛具体问题或展示反常现象；不要先念论文题目和作者。
4. 每个场景只解释一件事。短版约8秒换场，长版约10秒；场景内部通过
   实际配音的关键词时间触发显现、移动、聚类、标注和数字增长。
5. 口播、画面、字幕分工：口播讲因果，画面演示过程，字幕便于理解。
   屏幕只放短标题、少量标签与数据，不展示口播全文或项目符号段落。
6. 使用问题、预测、揭晓、反例、证据、限制、回扣；不反复概述论文五模块。
7. 类比标注“机制示意”，不能把示意图当医学影像或实验结果。
8. 指标比较使用统一零基线，标出论文来源。百分点与百分比区分；
   分割重合度不说成诊断准确率，研究结果不包装为临床可用结论。
9. 结尾回答开场并指出边界，不要求观众虚假点赞，不承诺爆款。
10. 审核失败则修订脚本，不用弱化审核规则换取通过。

## 视觉语法

- question：问句快速入场，角色表情、结果预告。
- domain_shift：两家医院或两个数据域，图像风格切换，轮廓错位。
- error_loop：错误自监督形成反馈环，错误信号逐步放大。
- graph：相似节点连边并移动到同类簇；抽象说明，非真实聚类结果。
- prompts：共性和差异两路提示汇入特征，不能当作文本提示的真实实现。
- comparison：证据支持的横向条形图，数字增长，差值只用百分点。
- boundary：研究与临床部署的界线，谨慎说明不确定性。
- takeaway：回扣开场，用两个短句保留结论。

短版9:16、720×1280；长版16:9、1280×720。字体、画面、转场及音效由
Python/Pillow/MoviePy生成；不下载他人视频、音乐或未经授权的素材。

## 验证与迭代

检查真实配音、字幕时间边界、关键词事件、帧间差异、完整视频解码、
音量和声道、图文图片链接；报告目标与实际时长。
平台效果需要真实发布后测试前3秒留存、平均观看时长、完播率、收藏率，
不能以代码通过或动画存在来断言观众会喜欢。

## 用户提供的参考

- 作者：全全探索局；标题：《为什么深海巨兽，偏偏就是找不到？》。
- 小红书内容ID：`6a61bd7a000000000f03feab`。
- 用户提供的链接标题可见；云环境代理拒绝页面，未读取正文、视频或互动数据。
- 可借鉴的标题结构：建立常识预期 → 反转/矛盾 → 提出解释需求。
- 对应论文开场：同一个AI，为什么换家医院就不准？
- 不声称已看过整条视频，也不以用户分享文案中的“40”认定播放量或点赞。

## 本次用户补充标准

严格五模块顺序；Hook先输出；术语转日常比喻并直接画出来；结尾明确
对学生的学习启发，不凭空许诺考研、就业成效；结尾一页总结图；
配音用词级时间戳同步动作；可配置轻量BGM；独立模型事实审查。
长版初始口播预算1500～2000汉字，真实时长以音频测量为准，
不足十分钟时扩展有证据的解释或调整合适语速，不靠重复、空白填满。
Manim用于有真实公式或轨迹需求的镜头；医学论文无运动轨迹时不强行插入机器人动画。
